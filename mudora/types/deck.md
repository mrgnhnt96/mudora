# Slide decks

**Marker:** `<meta name="mudora-type" content="deck">`
**Starter:** use the Slides artifact type from quickstart

- Use plain language and keep it less formal. Use fewer slides than the first instinct; cut any slide that isn't needed.
- Give each slide only the problem and a possible solution, with brief evidence. No power statements.
- Don't overstate one example. "One user waited 23 minutes" is better than repeating the number as if it were typical.
- Check product claims against the code before stating them.
- Propose the fix the user wants to propose. Don't invent one. Ask when unsure.

## Checklist

- Is every slide needed, with only a problem, a possible solution and brief evidence?
- Is any single example presented as if it were typical?
- Is every product claim checked against the code?
