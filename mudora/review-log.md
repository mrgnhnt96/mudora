# Review log

Every headless review appends its findings here (`review_page.py` does it). This is the one place review feedback is kept across sessions and projects, so the docs get better over time.

How to use it:

- **Writer, after deciding the findings:** replace that entry's "Decisions" line with one line per finding: `1 kept`, `3 dropped: <why>`.
- **Before writing or revising a page:** skim the "Patterns" list below.
- **When a kind of finding shows up in two or more reviews** (on different pages), add it to "Patterns", and turn it into a rule: in that type's `types/<type>.md` Checklist if the pages were one type, otherwise in SKILL.md's "Rules for every page". The reviewer reads those rules, so it starts checking for it too.

## Patterns

- Words from inside the work left unexplained (tool names, people's names, team shorthand). Already rule-worthy: see SKILL.md.
- TL;DR rows that state plans or estimates as if they were measured results.
- Open questions the page already answers elsewhere.
- Several cutoffs or version numbers for the same thing that don't match.
